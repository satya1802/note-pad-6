<!-- sdlc:auto:start overview -->
note pad 6 is a two-app note-taking project generated by the Quorq AI SDLC platform: a Svelte 5 + Vite frontend with approved, reviewed screens (currently running on seeded sample data) and a Flask 3 backend that implements a real API for registration/login and CRUD note endpoints backed by SQLAlchemy models (User, Note) with PostgreSQL in production and an automatic SQLite fallback for local development. Auth uses Flask-Login session cookies, the frontend calls the API via a shared `apiFetch` helper, and the approved stack also names PostgreSQL 16 and AWS for deployment.
<!-- sdlc:auto:end overview -->

- Docker and docker-compose (optional, for the PostgreSQL service in docker-compose.yml)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. cd frontend && npm install
3. cd backend && pip install -r requirements.txt
4. (Optional) docker-compose up -d db to start a local PostgreSQL 16 instance; without it the backend falls back to a local SQLite file (app.db)
5. (Optional) set DATABASE_URL, JWT_SECRET_KEY, and ALLOWED_ORIGINS for the backend, and VITE_API_BASE_URL / VITE_API_SECRET_KEY for the frontend, per the code's os.getenv/import.meta.env usage
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- One Flask blueprint per architecture component that owns endpoints (api.py for auth, web_frontend.py for notes), registered in the app factory
- Route handlers delegate business logic to a services module (app/services/*) rather than implementing it inline
- SQLAlchemy models use PostgreSQL-specific types (CITEXT, TSVECTOR) with @compiles fallbacks so the same models work on SQLite for local/dev/test runs
- Database falls back to SQLite via DATABASE_URL default so the backend runs with zero external services out of the box
- Frontend screens live one-per-file under src/screens/, built from a shared UI component vocabulary in src/lib/ui/
- Frontend API calls go through a single apiFetch helper (src/lib/api.ts) that attaches bearer/session auth and normalizes errors as ApiError
- Session/auth handled via Flask-Login (cookie-based) on the backend; CORS configured with credentials support for the separate frontend origin
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to create PostgreSQL-specific columns (CITEXT/TSVECTOR) locally | No action needed for local dev: without DATABASE_URL set, the backend falls back to sqlite:///./app.db where these types compile to VARCHAR/TEXT automatically |
| Frontend cannot reach the backend / CORS errors in the browser | Ensure the backend's ALLOWED_ORIGINS includes the frontend's dev origin (defaults to http://localhost:5173 and http://127.0.0.1:5173 when unset) and that requests include credentials |
| `pytest` run from backend/ fails with 'ModuleNotFoundError: app' | Run pytest from the backend/ directory where pytest.ini sets pythonpath = . so `import app` resolves |
| Session cookie not persisting across frontend/backend origins | The backend sets SESSION_COOKIE_SAMESITE=None and SESSION_COOKIE_SECURE=True, which requires HTTPS; for plain HTTP local dev, calls must still include credentials via apiFetch's credentials: 'include' |
| Playwright e2e tests fail to start the backend | test:e2e expects a Python virtualenv at backend/.venv with dependencies installed; create it with `python -m venv .venv && .venv/bin/pip install -r requirements.txt` in backend/ before running npm run test:e2e |
<!-- sdlc:auto:end troubleshooting -->
